\section{RA-GSの実装}\label{sec:implementation}


提案手法であるRefractive-Aware Gaussian Splatting(RA-GS)は、Gaussian Splattingのオープンソースフレームワーク gsplat~\cite{ye2025_gsplat} を拡張して実装した。
コードリポジトリは\url{https://github.com/unotaiki/Refractive-Aware-Gaussian-Splatting}にて公開している。
実装･検証にかかる時間の制約により、合成データ環境では、3DGS~\cite{Kerbl2023ToG_3DGS}、実環境では2DGS~\cite{Huang2024SIGGRAPH_2DGS}を採用している。
合成データ環境においては、カメラパラメータを真値を既知として与え、画像解像度は800 $\times$ 800 pixelsをそのまま入力した。
実環境においては、前述の\cref{sec:camera-calibration}で推定したカメラパラメータを用いる。
カメラ位置に対する水面の位置は、RealityScanでアライメント後、同ソフトウェア上で水際の点群を基準にして水面を$xy$平面に合わせるように手動で設定した。
解像度は1/4にダウンサンプリングした画像を用いる。
RA-GSの実装を含めた、全ての過程において屈折率$n$を1.33で固定して与えている。

カメラ視点からの屈折をモデル化するパラメータ変換は、PyTorch~\cite{paszke2019pytorch} のカスタムautograd関数として実装し、gsplatの微分可能ラスタライザおよび最適化パイプラインに統合した。
勾配計算は陰関数定理を用いた効率的な実装により、カメラ姿勢と水の屈折率に対する勾配計算も可能とした。
一方、位置補正に関するヤコビアンは明示的に導出することで計算を行っている。
補正するGaussianは中心位置の$z$座標に関して$p_z < z_\text{water level}$ を満たすものに対してのみ適用し、地上のGaussianには適用しない。
\cref{sec:position-correction}で述べた中心補正における4次方程式の求解には、ニュートン法を採用した。
% \note{どの程度で、収束するかを定量的に示す}
これらの処理により、オリジナルの3DGS実装~\cite{Kerbl2023ToG_3DGS} と比較して計算コストは最大で3倍程度増加するが、これは実用上許容される範囲のオーバーヘッドである。
% \note{全体で何倍処理時間が増えるかを説明する。Positioin Correctionのみではなくヤコビアンの計算にもボトルネックがある}

最適化プロセスにおいては、3DGS~\cite{Kerbl2023ToG_3DGS} の Adaptive Density Control(ADC)を採用し、ハイパーパラメータについても標準設定に準拠した上で、30,000イテレーションの学習を行った。 
なお、合成データ環境においては、勾配計算の実装を簡略化するため、ガウシアンの球調和関数の次数は0に固定しており、色は視点に依存しない設定(View-independent)としたが、
実環境における2DGSの実装では、次数を3とした球面調和による視線依存を実現している。 
ガウシアンの初期化に関しては、合成データによるシミュレーション環境では、水深約10mの位置に平面状の点群を配置して初期化を行い、
実環境においては、前述の\cref{sec:initialization-of-gaussians} で述べた方法で初期化を行った。

すべての実験は、NVIDIA RTX 3090 GPU 1台を使用して実施した。

\section{メッシュ抽出}\label{sec:mesh-extraction}
RA-GSで得た屈折を除外したGaussianモデルからのメッシュ抽出に関しても、合成データと実環境で異なる方法を採用している。

\paragraph{合成データ}\label{subsec:mesh-extraction-synthetic}
3DGSを使用した合成データに関しては、軽量な処理パイプラインを採用した。
具体的には、まず3DGS-to-PC~\cite{Stuart2025ICCV_3DGS-to-PC} を用い、各ガウシアンの体積に応じた確率的サンプリングを行うことで初期点群を生成する。
次に、ノイズを除去するため、CloudCompare~\cite{girardeau2016cloudcompare} を用いて外れ値フィルタリングを適用する。 
フィルタリング後の点群は水平面上の2Dグリッドへと離散化され、各グリッドセル内の高さの中央値(Median height)を算出することでハイトマップを作成する。
このハイトマップに基づき、最終的な表面整合点群を再構成する(\cref{fig:extract_surface_aligned_pc})。 
% なお、グリッド解像度およびフィルタリングのパラメータは、表面の平滑性と詳細構造の保存のバランスを考慮し、データセットごとに調整を行った。

\paragraph{実環境データ}\label{subsec:mesh-extraction-field}
2DGSを使用した実環境データに関しては、Truncated Signed Distance Function (TSDF) Fusion~\cite{Curless1996SIGGRAPH_TSDF} を用いたMesh抽出を採用した。
TSDFに入力するDepth Mapは、RA-GSで得たGaussianモデルを深度レンダリングすることで得る。
Depth Mapの算出には、2DGS~\cite{Huang2024SIGGRAPH_2DGS}で示された定量評価に従い、Median Depthによる深度を採用している。
実装には、Open3D~\cite{Open3D}のAPIを使用した。

TSDF Fusionにおける諸パラメータの決定は入力データの空間解像度をもとに決定した。
\cref{sec:field-dataset}による実環境データでは、カメラ高度\qty{12}{m}、画像は1/4にダウンサンプリングされているため、そのGround Sample Distance(GSD)は\qty{13}{mm}である。
このことから、Voxel Sizeには、その3倍程度の\qty{3}{cm}を、
Truncated Thresholdには、さらにその3倍程度の\qty{10}{cm}を設定した。
